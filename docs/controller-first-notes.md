更新：2026-09-09。用户要求把真实控制、自动战斗和完整肉鸽闭环提到视频
流水线之前。**已确认的是优先级、Windows/MuMu 目标描述，以及用户报告现有

## 两条路线及建议顺序

| 路线 | 解决什么 | 仍然缺什么 |
| --- | --- | --- |
| A：接入现成 MAA／MaaCore 肉鸽自动化 | 在不训练本项目模型的前提下，建立指定环境上的自动化基线与结果记录 | 环境、主题/难度/队伍、受限测试、结果验收；不保证目标结局或稳定通关 |
| B：用 MaaFramework 执行自研策略 | 提供截图、点击和滑动等底层能力，供本项目未来策略调用 | 识图、状态跟踪、菜单/战斗策略、坐标校准、恢复和实测；SDK 本身不是肉鸽决策策略 |

建议先评审 A 的小范围接入，再逐步建设 B。A 的结果始终归因于 MAA 自带
策略，不能计成本项目模型的能力；如果用户要求从第一步就由自研策略决策，
需要单独确认该范围及感知/策略依赖。实际训练仍按用户要求留到后期。

用户在 2026-09-09 确认游戏平台为 Windows PC，模拟器为 MuMu 安卓设备，
并随后回答现有 MAA 可以正常连接。这是用户提供的信息，不是本项目已经
观测、连接或验证过的环境；具体 MuMu 版本未知，不能直接写成 MuMu 12
或套用某个示例端口、路径和多开实例。不要再重复询问平台或现有连接状态。

下一步是评审下面的最小接入建议。准确的 MuMu/MAA 版本、指定实例、客户端
语言和截图尺寸，是确定版本相关接口及实测前的配置要求，不必在方案讨论前

约定；H01 的主题、难度、结局和队伍也仍待确定。

## 待确认的第一段交付：Windows 本地最小接入

**建议先做 A 路线的接入校准，再做 MAA 自带策略的战斗／整局基线，最后
逐步接入本项目策略。** 另一选择是直接走 B，让自研策略从一开始就决策，
但这同时依赖尚未实现的识图、状态跟踪和战斗动作。本段只提出第一小段的
范围，等待用户确认；不是完整规格、批准的接口或文件级实施计划。

拟在运行 MuMu 的 Windows PC 上使用一个本地小工具，明确选择 MaaCore、
匹配资源、连接配置和目标实例，不开放网络控制服务，不自动扫描设备，也不
改写已有 MAA 配置。默认只走离线验证；设备模式必须显式选择且符合 H04
约定。版本与资源不匹配时不以“现有 MAA 能连接”为由继续猜测兼容性。

| 检查点 | 拟做什么 | 怎样验收 |
| --- | --- | --- |
| 离线边界 | 用替身模拟连接、截图和输入 | 默认不加载 SDK、不接触设备；失败、超时、错配和迟到结果能明确记录并阻止后续动作 |
| 项目连接与截图 | 只连接明确选定的 MuMu 实例，主动请求一次截图 | 分别记录连接状态、截图请求及完成证据和尺寸；读取缓存本身不算新截图证明 |
| 一次菜单输入 | 在你确认的页面及按钮上只提交一次校准输入 | 绑定输入前的画面及坐标；之后主动取新截图、由你核对实际效果，不能只凭 SDK 返回成功 |
| 结束与记录 | 完成后结束，或遇到超时／结果不明就停止后续派发 | 不盲目重试；请求、返回、画面证据与实际效果分别记录，无法确认则记未知 |

第一段不启动肉鸽任务、不自动战斗、不购买或处理账户，也不启动模型或训练。
一次原始校准点击**不等于**现有抽象 `select` 已经映射到游戏按钮；菜单选项
识别、坐标映射和战斗动作需要后续单独设计。新截图的证据也不要求画面像素
必然变化：静止页面可能相同，应核对请求时序及来源，再判断输入是否生效。

设备测试前应停下 MAA GUI 和其他控制器的自动任务，避免争用；本项目不能
声称已经自动保证跨进程独占。停止本项目只表示停止继续派发，不代表暂停
游戏，也不能保证原生已提交输入被撤销。私有配置、截图和原始日志只留在
私有位置；公开仓库仅保留去敏的结果摘要和合成测试。

需要确认的设计问题是：**是否先按这个“Windows 本地、连接＋新截图＋一次
经批准的菜单输入”的最小范围推进？** 同意该范围后再完成规范、评审和实施
计划；这份设计确认不代替具体设备测试范围与授权。战斗／整局实验仍依赖
H01/H07，实际训练继续延期。

## 本次核查到的 MAA 接口边界

本次检查固定于 MaaAssistantArknights 提交
`e523b2038c6790f5f45d95c2e1de84c3450cc357`，不是“最新版”承诺。
协调者直接读取了下面六个官方文件，核对返回内容的 Git blob 身份并检查
关键行；独立源码检查得到相同的主要结论。没有构建或加载 MaaCore，没有
连接设备，也没有改变现有配置报告的固定研究快照。

1. **语言绑定不等于完整 C API。** 所查 Python 包装提供同步 `connect`、
   `get_image`、`append_task`、`start`、`stop`、`running`；C API 另有
   `AsstAsyncConnect`、`AsstAsyncClick`、`AsstAsyncScreencap` 三个异步接口。
   不能编造现成的同名 Python 异步方法。Python `get_image(size)` 已调用
   `AsstGetImage`，但读取的是上次截图，不是发起新截图。Python `stop`
   停止并清空该实例任务，与现有“停止本项目代理”语义不同。
2. **肉鸽任务不等于通关模式。** `Roguelike` 的 `mode=0` 是刷分、尽量
   到达更高层，并非通关保证。模式 1 会在一层投资后退出；2 和 3 被拒绝。
   不能拿刷资源或主动退出的配置证明完整目标通关。
3. **次数和目标必须显式约束。** `starts_count` 默认是 2147483647；未来
   实验应明确有限次数及独立总时限。所请求难度未解锁时会改用最高已解锁
   难度，因此配置值不是“实际按该难度进行”的证明。
4. **队列结束不是通关证据。** `Assistant.cpp` 中，任务链错误之后仍可能
   因队列为空发出 `AllTasksCompleted`。任务链完成和队列完成必须分别记录，
   不能直接写成 `game_clear_verified=true`。
5. **结算信号有范围和缺失情况。** 所查插件用 `RoguelikeSettlement` 的
   `details.game_pass` 报告识别结果，只在 `Exp` 或 `BlackFlowBabyAnimal`
   模式启用。等待完整结算页失败时会直接返回、不发这个回调。缺失应记未知；
   已有信号仍需保留结算画面、身份及目标条件供验收。
6. **参数更新不等于实时策略注入。** 所查 `RoguelikeTask::set_params` 在
   任务运行时返回 false。不能假定通过通用参数更新接口就能随时接管整局。

### 最小接入的补充源码边界（2026-09-09）

在同一固定提交上，协调者与独立研究者进一步只读核对了以下关键段落。
本段依据保留 TLS、有限超时和大小上限的公开原始源码读取结果；未运行
所读源码，也未验证用户安装包与该提交相同。

- **请求编号和结果分开。** `Assistant.cpp` 745–779 行入队并返回编号；
  `block` 等待没有期限。884–917 行先唤醒等待者，再排入带
  `async_call_id`、`what` 和 `details.ret` 的回调。926–950 行异常恢复
  还可能丢弃队列、推进完成编号。不能把非零编号或阻塞返回当作成功，也不
  保证每个请求都会收到正常回调。
- **缓存不绑定请求。** `Assistant.cpp` 396–404 行读取缓存；
  [Controller.cpp](https://raw.githubusercontent.com/MaaAssistantArknights/MaaAssistantArknights/e523b2038c6790f5f45d95c2e1de84c3450cc357/src/MaaCore/Controller/Controller.cpp)
  147–158、520–529 行读取／缩放或更新共享缓存，空缓存分支仍会构造指定
  尺寸的图像对象。因此非空 PNG 和锁都不是某次新截图的证明；设计需排除
  同实例其他截图／任务写入，关联请求和回调，并保守记录时间与不确定性。
- **点击有坐标缩放。** `Assistant.cpp` 291–294 行与 `Controller.cpp`
  173–177 行把点交给
  [ControlScaleProxy.cpp](https://raw.githubusercontent.com/MaaAssistantArknights/MaaAssistantArknights/e523b2038c6790f5f45d95c2e1de84c3450cc357/src/MaaCore/Controller/ControlScaleProxy.cpp)
  65–72 行，再乘控制倍率。该文件 15–58 行检查分辨率／16:9 比例并计算
  倍率。应校准选定 SDK 的缩放坐标，不可直接照搬 Windows 桌面坐标、原始
  设备像素或重复乘倍率；此处不预设用户实际截图尺寸。
- **停止任务不是撤销单次调用。** `Assistant.cpp` 526–545 行的停止逻辑
  清任务列表及状态缓存，并不清异步调用队列；`running()` 只是任务运行
  标志。到期或停止后应拒绝后续输入，不能据此声称在途输入已取消或可安全
  重试。该结论不等于已实现适配器的停止／恢复逻辑。
- **Python 截图包装需单独检查。** 所查 `asst.py` 148–162、272–276 行
  接受字节容量，返回整个分配缓冲区，未按实际长度截取；
  [AsstCaller.cpp](https://raw.githubusercontent.com/MaaAssistantArknights/MaaAssistantArknights/e523b2038c6790f5f45d95c2e1de84c3450cc357/src/MaaCore/AsstCaller.cpp)
  15、256–267 行用无符号 `-1` 表示失败，该值仍满足包装的 `got > 0`。
  这是静态返回值风险，未运行复现；不能以非 `None` 作为有效截图证明。

这些结论用于约束待讨论方案，不是对 MAA 全项目的审计或兼容性认证。正式
设计仍需选定 SDK／资源版本，覆盖错误长度、缺失／迟到回调、缓存竞争和
坐标校准，且默认路径继续离线。

## MaaFramework 路线需保留的已有检查

既有 [MaaFramework 说明](maaframework-integration-notes.md) 固定于 `v5.12.3`，
它与上述 MaaCore 来源不是同一个项目。已有记录指出：异步作业返回不等于
成功，`wait()` 没有超时参数，截图 getter 读取最新缓存而不是某个作业的
不可变帧。因此未来适配器需要串行协调和自己的期限；期限到达不证明已经
提交的输入被取消。本次没有重新运行这些 SDK。

## 拟议验收顺序，尚未执行

1. **确定环境和设计。** 得到目标平台/设备信息后，评审最小接口规范、坐标
   空间、运行限制、失败状态、日志隐私和人工停止方式，再写文件级实施计划。
2. **离线适配器测试。** 用注入的替身测试连接失败、过期/错配截图、尺寸变化、
   超时、重复回调、迟到结果和异常清理。默认路径不导入 SDK、不发现设备、
   不执行动作；替身通过不等于真实兼容性。
3. **H04 的指定目标校准。** 先有界连接并读取截图，再执行用户确认的单次
   无购买/账户操作输入，读取新画面核验实际效果。不确定时停止后续派发，
   不通过盲目重试猜测输入是否已经发生。
4. **监督下的一场战斗。** 固定关卡和队伍，记录控制请求、任务状态、画面证据、
   超时/失败与人工介入，不能只检查返回值。
5. **H07 的有限整局实验。** 固定主题、难度、结局、总次数/时限及停止条件。
   每次尝试均计入，分别记录成功、失败、未知和人工介入，保留结果证据与
   策略来源。一次成功不等于可靠自动通关，MAA 基线也不等于模型进步。

这些是待评审的阶段目标，不是新接口已获批准的声明。H04/H07 不替代真实
录像 H02/H03 或训练启动的独立决定；H08 仍是更后的另一个视频设计事项。
